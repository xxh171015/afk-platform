# AFK 是「不等」，不是「不问」：agent 的取舍带类型交出来，由 Spec 轴下结论，人在合并时定

agent 在执行阶段遇到票、需求、契约、现有代码对不上时，以前只有两条路：输出 `cannot-proceed` 让票 blocked，或者自己定、写一句自由文本。前者在页面上像失败，后者没有代价，于是 S-1…S-28 里 176 条取舍对 2 次停下，自由文本在开 PR 前没有任何环节会读。现在定为：agent 继续做、不等人，但每个会改代码的阶段把取舍写成带类型的 Decision（`choice`、`conflict`、`known-gap`、`deferred`、`workaround`）；票级和需求级的 Spec 轴读决策日志，对每条 `conflict` 和 `known-gap` 下 Ruling（允许、必须改、必须人来定），缺结论就是 `invalid-output`；必须人来定的和没被做掉的 `deferred` 不挡流程、不叫人，开 PR 时列在验收包和 PR 描述最前面，由本来就要出现的合并人来定。`cannot-proceed` 只留给三种情况：缺做下去必需的东西、要改没批准的保护路径、契约非改不可。

## Considered Options

- **停下来问**（`conflict` 一律 `cannot-proceed`）：最稳，但每张票都可能叫人回来，和人只在规划和合并时出现的前提相反。
- **待处理队列加一类「待确认的决定」**，票不停、人随时去答：人仍被中途叫回来，答复又不挡票，常常答了也没用上。
- **开 PR 前未解决的让收尾 blocked**：PR 里不带悬而未决的事，代价是开 PR 前多叫一次人；合并时人本来就在，同样能定。
- **只在需求级下结论**：省掉票级审查，但 T-25 那种 implement 自己写明的缺口要到收尾才修，修的代价更高。
- **不分类型，平台把所有取舍都交给人**：人被小事淹没，又回到没人看的状态。

## Consequences

- 两处例外会挡住流程、叫人：门禁发现测试名少了（改名也算），以及 Recheck 判定审查之后的修复改变了已有行为或放松了检查。改测试是让检查失效的取舍，不能留到合并时才看；这两种情况在真实记录里少见，叫人的次数有限。
- 覆盖层要举例说明什么是 `conflict`（契约没写的状态码、字段、校验；票和 User Story 写法不同；票的约束和 tdd 冲突），否则模型仍会把它们当小事。覆盖层绑定 skills SHA 的约束不变（[ADR 0002](0002-afk-runs-execute-matt-skills-under-an-overlay.md)）。
- 每个阶段仍是全新会话，靠 `/context` 里的决策日志接上：后面的阶段和兄弟票看得到前面的决定，推翻一条要新写一条 `conflict`。
- 票级 Spec 轴从此有实际的活；不提供关掉票级审查的选项。
