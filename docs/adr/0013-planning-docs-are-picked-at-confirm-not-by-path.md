# 规划文档由人在 confirm 时选定，不按路径挑

规划仓库里这次规划改的文件，在 `plat spec confirm` 时由人选定交给平台，不按固定路径或类型挑。confirm 列出规划仓库里所有本地改动（没提交的、新建未忽略的、提交了没推送的、删除的；本机专用的规划文件不在清单里），人选哪些交给平台；有改动又没选时不放行。规划仓库认不出、导入时有改动却在页面确认，都要说出来，不能悄悄放行。本篇取代 [ADR 0005](0005-planning-docs-go-with-the-spec-committed-by-the-platform.md) 里「规划文档是哪几个路径」的部分；0005 其余内容不变：平台替人提交、规划提交是集成分支的第一个提交、补丁合不进去时 retry / waive。

## Considered Options

- **按路径或文件类型挑**（比如只带 Markdown、或写死 `GLOSSARY.md` / `docs/adr/` / `AGENTS.md`）：这次的问题就是范围写死，规划时一起改的 `docs/design.md`、`docs/specs/*.md` 带不上。
- **全部本地改动都送**：会把规划前的未提交改动一起交出去。
- **开始规划时给工作区拍快照，自动区分规划前后**：能处理同一文件两种改动混在一起的情况，但要多一套快照、逐文件三方合并、切换分支检测和收走规则，而这种情况很少；第一版方案因为太复杂放弃。
- **只把文档挂到 `/context/` 给 worker，不提交**：仓库里的文件还是旧的，agent 会看到两个版本；这些文档也到不了默认分支。ADR 0005 已经放弃过「文档正文存在平台、一直从平台挂载」。
- **要求开始规划前工作区干净**：把整理工作推给人，而「有没提交的改动又开始规划」正是要支持的情况。
- **其他仓库的本地改动**：只看规划仓库。其他仓库的票照旧在 `/context/domain/` 读规划提交里的术语表和 ADR；`/context/domain/` 的挂载范围这次不变。

## Consequences

- 补丁只含人选中的文件；没选中的留在本机，worker 读不到。清单为空时 confirm 和现在一样直接执行。
- 选中的文件名像密钥（`.env`、`.env.*`、`*.pem`、`*.key`、`id_rsa*`、`*.p12`）时拒绝。
- 人确实不要导入时记下的改动时，用 `leavePlanningChanges` / 「不带这些改动，照样确认」明确放弃，验收包和 PR 描述注明。
- `@afk/shared` 的 `PLANNING_DOC_PATHS` 不再决定补丁范围，只留给 `/context/domain/` 挂载用。
