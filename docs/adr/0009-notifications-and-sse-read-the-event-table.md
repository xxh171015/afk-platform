# 通知和 SSE 从事件表出发，按事件 id 去重

通知要和已经记下的事实一致，重启不能把同一件事再发一遍。状态变化已经由触发器写成事件（[ADR 0008](0008-events-are-written-by-database-triggers.md)），再从领域快照的边沿另算一遍通知会和事件分叉；磁盘告警、agent 暂停、令牌到期还会完全绕开事件表。所以派发器和 SSE 都改读事件：触发器在事务提交后 `pg_notify`，API 一条 LISTEN 连接按游标读新行。通知游标持久化在实例上；SSE 只推当前连接，不补历史。系统状况显式插入 `type=system` 的事件，和人的操作一样不靠状态触发器。

## Considered Options

- **继续用快照边沿 `notify()`，系统状况各自去重**：实现短，但三条旁路，进程重启会重发，和事件对不上。
- **轮询事件表**：不断线语义简单，但空转和延迟都差。
- **`pg_notify` + 游标（选中）**：提交后才送达，断线按游标补读，和触发器同一来源。

## Consequences

- 路由不再手动发布失效；快照对比那条派发路径退役。
- 磁盘 / 暂停 / PAT 的边沿旗标只决定要不要插事件，不直接发通知。
- 同一 Spec 从窗口内第一条事件起 30 秒固定窗口合成一条通知；飞书发送的去重键用这条事件的 id。
